## 0. Поправим логику McpToolProvider

Сейчас он сообщает llm обо всех доступных командах.

Добавляем ему возможность видеть для конкретного agentId только разрешенные для него mcp tools

Для этого добавляем чат комаднду для TalkWorker
@@talk(agent --addtool tool_name)
@@talk(agent --listtools tool_name)
@@talk(agent --cleartools tool_name)

Все это работает полностью аналогично существующим командам
@@talk(agent --addrule "текст")
@@talk(agent --listrules)
@@talk(agent --clearrules)

С одним отличием: AgentrulesMemoryProvider использует категорию:
const val CATEGORY = "rules"

А McpToolProvider будет использовать категорию:
const val CATEGORY = "tools"
 И будем работать по такой логике: Если в памяти агента есть tools, то значит он имеет право работать только с указанными,
	иначе работает как сейчас - со всеми доступными tools

Этот tool при выполнении должен инициализировать агента.
Ровно так, как это делает метод TalkWorker.processMessage

 1. agentName для идентификации агента и передачи в aiAgentFactory.getOrCreate    (конкретно в этом кейсе agentName = "git_file_investigator")
 2. chatId чтобы знать в какой чат отправлять нотификации о работе и статистике
 3. systemPrompt.
	Замечание:
	systemPrompt у aiAgentFactory.getOrCreate - deprecated (будет пока всегда пустой). 
	Мы должны уметь задавать агенту AgentSystemPromptMemoryProvider : MemoryProvider,
	который по id агента отдаст ему его текущий ситменый промпт.
	Системный промпт предлагаю хранить и настраивать через механизм, который используется в  AgentRulesMemoryProvider,
	т.е. через память агента (методы agentMemoryRepository.getFact и agentMemoryRepository.upsertFact) с категорией "systemPrompt"
 4. defaultModel: () -> ModelSettings,
 5. defaultContext: () -> AContext

## 3. LocalMcpService: get_file_analisys

### Параметры
== description ==
Получает анализ по полному имени файла
== properties ==
file_full_path: string (required)
== возвращаемый ответ ==
{
 "status": "ok",
 "file_full_path": "file_full_path"
 "content": "текстовый анализ файла"
 "error_text": "текст ошибки"
}


### Как работает
0. Агента тут нет, только код.
1. Берет полное имя файла и ищет его в FileAnalisysEntity
2. Если находит - возвращает результат
3. Если не находит то
 - скачивает файл
 - ищет зарегистрированный tool в списке MCP с именем analyze_code_content
 - выполняет его для file_full_path
 - если в результате error=null или пусто, а content не пустой - сохраняет его в FileAnalisysEntity
 - возвращает его результат (не ображается напрямую, а находит tool по имени).
