## Q1: "какие основные возможности агента, какой класс реализует"
Основными возможностями агента, по предоставленному контексту, являются:

1. **Управление жизненным циклом агента**: агент может проходить через различные стадии жизненного цикла, такие как создание, запуск, выполнение, завершение или сбой.
2. **Выполнение стратегии**: агент может выполнять определенную стратегию для обработки входных данных и производства выходных данных.
3. **Взаимодействие с компонентами**: агент может взаимодействовать с различными компонентами, такими как ToolRegistry, AIAgentPipeline, AIAgentContext, для выполнения своей функциональности.
4. **Обработка событий**: агент может обрабатывать различные события, такие как ошибки, исключения, завершение выполнения, и т. д.
5. **Регистрация и управление**: агент может регистрироваться и управляться через службу AIAgentService, которая обеспечивает создание, удаление, запрос и управление агентами.

Классы, реализующие агента, это:

1. **AIAgentService**: абстрактный класс, который предоставляет базовую функциональность для управления агентами.
2. **AIAgentRunSessionImpl**: класс, который реализует выполнение жизненного цикла агента.
3. **AIAgentFeature**: интерфейс, который определяет функциональность агента и его взаимодействие с другими компонентами.

Эти классы и интерфейсы обеспечивают базовую архитектуру для создания и управления агентами, а также выполняют различные задачи, связанные с их жизненным циклом и выполнением.

## Q2: "как конфигурируется агент"
Чтобы конфигурировать агента, необходимо выполнить несколько шагов, используя предоставленные классы и методы:

1. **Создание агента**: Для начала необходимо создать экземпляр класса `AIAgentBuilder`, который позволяет конфигурировать агента. Это можно сделать, вызвав один из конструкторов или методов, предоставляемых классом `AIAgentBuilder` и его наследниками (`FunctionalAgentBuilder`, `PlannerAgentBuilder`).

2. **Установка конфигурации агента**: Используйте метод `agentConfig` класса `AIAgentBuilder`, чтобы установить конфигурацию агента. Вам необходимо передать объект `AIAgentConfig`, который содержит настройки для агента, такие как настройки промпта, модель, лимиты итераций и стратегия обработки инструментов.

3. **Установка функций**: Используйте метод `install` класса `AIAgentBuilder`, чтобы установить функции в агент. Этот метод принимает функцию и конфигурацию, позволяя настраивать поведение агента. Вы можете добавлять несколько функций, чтобы расширить возможности агента.

4. **Создание агента**: После того, как вы настроили все необходимые параметры, вызовите метод `build`, чтобы создать экземпляр `AIAgent`. Этот метод проверяет, что все необходимые поля правильно установлены, и применяет все настроенные функции к агенту.

Пример создания и конфигурирования агента может выглядеть следующим образом:
```kotlin
val agentBuilder = FunctionalAgentBuilder<Input, Output>()
    .agentConfig(AIAgentConfig(prompt = "Привет", model = "ru"))
    .install(MyFeature(), { config ->
        // настройка функции
    })
    .build()
```
Этот пример показывает, как создать агент с определенной конфигурацией и установить функцию `MyFeature` с кастомной настройкой.

Обратите внимание, что приведенный выше пример является упрощенным и не включает все возможные настройки и конфигурации, которые могут быть необходимы для реального проекта. Окончательный код будет зависеть от требований вашего приложения и используемых классов и методов.

## Q3: "как агент работает с историей сообщений"
Agent работает с историей сообщений посредством нескольких механизмов:

1. **AgentContextData**: Этот класс содержит историю сообщений (`messageHistory`) между агентом и пользователем. Инициализация этого класса происходит с использованием списка сообщений и других параметров, таких как стратегия откатов (`rollbackStrategy`) и дополнительные действия при откате (`additionalRollbackActions`).

2. **ChatMemory**: Этот класс обеспечивает возможность хранения и загрузки истории разговоров между агентом и пользователем. Он реализует функциональность, позволяющую агентам сохранять и восстанавливать историю сообщений между сеансами работы агента.

3. **JdbcChatHistoryProvider**: Этот класс предоставляет возможность хранить историю сообщений в базе данных с использованием JDBC. Он предназначен для управления чат-историей в SQL-базах данных и позволяет хранить и загружать историю сообщений между пользователем и агентом.

4. **HistoryCompressionConfig**: Этот класс реализует настройки для сжатия истории разговоров в стратегии одного запуска. Он позволяет задавать функцию, которая проверяет, превышена ли история сообщений определенный порог, и стратегию сжатия, реализующую то, как сжимать историю разговоров.

В общем, Agent может работать с историей сообщений посредством различных механизмов, включая сохранение и восстановление истории сообщений, хранение в базе данных и сжатие истории разговоров. Эти механизмы позволяют Agent сохранять контекст взаимодействия с пользователями и улучшать качество обслуживания за счет сохранения истории разговоров.

## Q4: "как реализованы стратегии компактизации контекста"
Стратегии компактизации контекста реализованы с помощью различных классов и методов в предоставленном коде. Вот некоторые из них:

1. **HistoryCompressionStrategy**: Этот абстрактный класс представляет собой стратегию сжатия истории сообщений в сессии агента. Он имеет несколько реализаций, таких как `WholeHistory`, `FromLastNMessages`, `FromTimestamp` и `Chunked`, которые определяют конкретные подходы к снижению размера контекста, сохраняя ключевую информацию.
2. **AgentContextData**: Этот класс содержит данные о контексте агента, включая историю сообщений, путь узлов и дополнительные действия для откатов. Он использует перечисление `RollbackStrategy` для определения стратегии откатов контекста агента.
3. **RollbackStrategy**: Это перечисление определяет стратегии откатов контекста агента. Есть две стратегии: `Default` (которая восстанавливает контекст агента полностью) и `MessageHistoryOnly` (которая восстанавливает только историю сообщений).
4. **StrategyEventContext**: Этот интерфейс определяет контекст событий стратегии, который включает функциональность и поведение, посвященные управлению жизненным циклом и операциями стратегий агентов.
5. **StrategyStartingContext**: Этот класс представляет контекст запуска стратегии агента. Он имеет свойства, такие как `executionInfo`, `strategy` и `context`, которые используются для инициализации контекста события стратегии.
6. **AIAgentPipelineImpl**: Этот класс реализует механизм пайплайна агента, который включает вызов обработчиков событий стратегии. Он использует методы, такие как `onStrategyStarting`, `onStrategyCompleted` и `onStrategyExecutionFailed`, для обработки событий стратегии.

Эти классы и методы вместе обеспечивают функциональность компактизации контекста в агенте, позволяя эффективно управлять контекстом и историей сообщений, а также откатывать контекст агента при необходимости.

## Q5: "как реализован tool calling"
В контексте реализации gọi tool (инструмент) в agent-фреймворке, parliament на базе Kotlin и других технологий, реализация происходит через следующие компоненты:

1. **ToolArgs**: Интерфейс, который представляет аргументы для операции инструмента. Он помечен как устаревший, поскольку аргументы инструмента теперь полностью обрабатываются через библиотеку KotlinX Serialization.

2. **EventHandler**: Класс, который позволяет подключаться к различным событиям в жизненном цикле агента, включая события вызова инструментов (tool call events). Этот класс предоставляет способ регистрировать обратные вызовы для разных событий, которые происходят во время выполнения агента.

3. **ToolCallStartingEvent**: Событие, которое возникает при вызове инструмента в системе. Это событие используется для захвата и описания вызова инструмента вместе с его аргументами, что помогает в отслеживании, логировании или обработке вызовов инструментов как части более крупного конвейера функций или рабочего процесса системы.

4. **McpTool**: Реализация инструмента, который вызывает инструмент MCP (Model Context Protocol) через клиент MCP. Этот класс служит мостом между интерфейсом инструмента агентского фреймворка и SDK MCP, позволяя использовать инструменты MCP внутри агентского фреймворка.

5. **ToolCallEventContext**: Контекст, который представляет информацию о вызове инструмента. Он включает в себя идентификатор запуска, идентификатор вызова инструмента, имя инструмента, описание инструмента, аргументы инструмента и контекст агента, связанный с вызовом инструмента.

В общем, вызов инструмента в этом фреймворке включает в себя создание события `ToolCallStartingEvent` при начале вызова инструмента, обработку этого события через `EventHandler`, и выполнение инструмента с помощью конкретной реализации инструмента, такой как `McpTool`, которая обеспечивает взаимодействие с внешними инструментами через соответствующие клиенты или API.
