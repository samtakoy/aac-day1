# День 24 — Цитаты, Источники и Анти-Галлюцинации: План Реализации

## Продуктовая задача

Доработать RAG так, чтобы LLM **обязательно** возвращала:
- Ответ с инлайн-сносками `[ИСТОЧНИК N]` после каждого утверждения
- Раздел `### Источники` со списком использованных ссылок (файл, метод, строка)
- Режим "не знаю": если контекст пустой — LLM обязана попросить уточнение

Проверить на 10 вопросах через `@@talk(rag --runtest)`.

---

## Анализ текущего состояния

### Где генерируется ответ

```
RagCommandHandler.handleRuntest()
    → ragSearchRepository.evaluate()   → /evaluate HTTP endpoint (RAG server)
                                           → PipelineExecutor → ContextFormatter.format()
                                           ← ragContext (текст чанков)
    → llmRequestUseCase.exec(systemPrompt, ragContext + question)
    ← answer (текст ответа LLM)
    → ragSearchRepository.saveRuntestResults()  → /runtest/save HTTP endpoint
```

**Ключевой вывод:** Цитирование — ответственность клиентской LLM (в Android).
RAG server отвечает только за качество и структуру предоставляемого контекста.

### Проблемы текущего `ContextFormatter.format()`

```
[CLASS] McpTool
File: .../McpTool.kt
Score: 0.823
--- McpTool ---
<code>
--- invoke ---
<code>
```

- Нет нумерации источников — LLM не знает как ссылаться на конкретный чанк
- Нет сводной таблицы источников в конце — LLM не знает file + line для финального списка
- Нет номеров строк в заголовках чанков

### Проблемы system prompt в `RagCommandHandler`

`handleRuntest` (строка ~156):
```kotlin
systemPrompt = """
Для каждого утверждения в ответе укажи источник.
...
""".trimMargin()
```
- Нет жёсткого формата → LLM делает "как хочет"
- Нет принуждения к инлайн-сноскам `[ИСТОЧНИК N]`

`handleRunparamtest` (строка ~217):
```kotlin
systemPrompt = ""
```
- **Баг:** пустой system prompt → LLM вообще не знает как отвечать

### Режим "не знаю"

Сейчас: если `results.isEmpty()` → возвращается текст "Ничего не найдено",
но LLM его **игнорирует** и генерирует ответ из своей памяти (галлюцинации).

Нужно: заменить текст на явный маркер `НЕДОСТАТОЧНО_КОНТЕКСТА`,
на который system prompt реагирует отказом отвечать.
Порог — только `results.isEmpty()`, новых параметров не добавляем.

## Детали реализации

### 1. `ContextFormatter.kt` — переписать `format()`

Нумерует каждый чанк сквозным счётчиком. Добавляет секцию `## Источники` в конце.

**Формат контекста на выходе:**

```
Found 3 relevant class(es) | ~4800 chars

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[CLASS] McpTool
File: .../mcp/McpTool.kt
Score: 0.823

--- McpTool [ИСТОЧНИК 1] (line 12) ---
class McpTool(...) : Tool<...> {
    ...
}

--- invoke [ИСТОЧНИК 2] (line 45) ---
override suspend fun invoke(...) {
    ...
}

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[CLASS] ChatRepository
File: .../chat/ChatRepository.kt
Score: 0.781

--- sendMessage [ИСТОЧНИК 3] (line 78) ---
suspend fun sendMessage(...) {
    ...
}

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
## Источники
[ИСТОЧНИК 1] McpTool.kt · McpTool · line 12 · .../mcp/McpTool.kt
[ИСТОЧНИК 2] McpTool.kt · invoke · line 45 · .../mcp/McpTool.kt
[ИСТОЧНИК 3] ChatRepository.kt · sendMessage · line 78 · .../chat/ChatRepository.kt
```

**Правила нумерации:**
- Счётчик сквозной по всему контексту, начинается с 1
- Каждый чанк получает уникальный номер
- Заголовок чанка: `--- declarationName [ИСТОЧНИК N] (line X) ---`
  - Если `declarationName == null`: `--- line X [ИСТОЧНИК N] ---`
- Секция `## Источники` — всегда в конце, после всех классов. Работает как справочник: LLM видит `[ИСТОЧНИК N]` в чанке, потом находит полный путь + строку в конце

**`formatFlat()` — не трогаем** (strategy=fixed, вне основного флоу).

### 2. `RagServer.kt` — сигнал "не знаю"

В обработчике `GET /search`, в уже существующей ветке пустого результата:

```kotlin
// БЫЛО:
if (ctx.packed == null || ctx.packed.groups.isEmpty()) {
    call.respondText("Ничего не найдено по запросу: $query")
    return@get
}

// СТАНЕТ:
if (ctx.packed == null || ctx.packed.groups.isEmpty()) {
    call.respondText(
        "НЕДОСТАТОЧНО_КОНТЕКСТА: по запросу \"$query\" ничего не найдено. " +
        "Уточните запрос или проверьте что индекс содержит нужный код."
    )
    return@get
}
```

Никаких новых параметров, никаких новых полей в конфиге.

### 3. `RagCommandHandler.kt` — system prompt

Единый val `CITATION_SYSTEM_PROMPT`, использовать в обоих методах.

```kotlin
private val CITATION_SYSTEM_PROMPT = """
Ты отвечаешь на вопросы по Kotlin кодовой базе, используя ТОЛЬКО предоставленный контекст.

Формат ответа СТРОГО ОБЯЗАТЕЛЕН:

### Ответ
Текст ответа. После каждого утверждения — инлайн-сноска [ИСТОЧНИК N].
Пример: "Отправка сообщений реализована в ChatRepository [ИСТОЧНИК 3] через suspend-функцию sendMessage [ИСТОЧНИК 3]."

### Источники
Список использованных источников (только те, на которые ссылался в ответе):
[ИСТОЧНИК N] ИмяФайла.kt · имяМетода · line X

Если контекст содержит "НЕДОСТАТОЧНО_КОНТЕКСТА" — напиши ТОЛЬКО:
"Не знаю. Уточните: ..." и задай один конкретный уточняющий вопрос.

Запрещено:
- Ссылаться на знания вне контекста
- Придумывать имена классов/методов которых нет в контексте
- Отвечать без раздела Источники

Отвечай на русском языке.
""".trimIndent()
```

**`handleRuntest`** — заменить весь `systemPrompt = """...""".trimMargin()` на `CITATION_SYSTEM_PROMPT`.

**`handleRunparamtest`** — заменить `systemPrompt = ""` на `CITATION_SYSTEM_PROMPT`.
