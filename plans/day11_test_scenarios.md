# Сценарии тестирования Day 11: PLANNER-группы и многоуровневая память

## Общее описание архитектуры памяти

Приложение реализует три слоя памяти:

| Слой памяти | Название | Хранение | Назначение |
|------------|----------|----------|------------|
| **Краткосрочная** | Short-term | Messages (история чата) | Текущий диалог, контекст разговора |
| **Рабочая** | Working | `ChatEntity.working_summary` | Контекст текущей задачи, саммари родительского чата |
| **Долгосрочная** | Long-term | `LongTermMemoryTable` | Профиль пользователя, навыки, предпочтения |

## Сценарий 1: Создание PLANNER группы и первичное планирование

**Цель:** Проверить создание нового типа группы чатов PLANNER

### Предусловия:
- Приложение запущено
- Пользователь на экране выбора групп

### Шаги выполнения:
1. Нажать "+" (создать группу)
2. Выбрать тип "PLANNER" (планировщик проекта)
3. Ввести название: "Мобильное приложение для фитнеса"
4. Подтвердить создание

### Ожидаемый результат:
- Создана группа с `ChatGroup.chatType = ChatType.PLANNER`
- Создан главный чат с `isPlannerMain = true`
- Пользователь перенаправлен в главный чат

### Проверка в БД:
```sql
-- Проверка типа группы
SELECT * FROM chat_groups WHERE type_id = 'PLANNER';

-- Проверка главного чата
SELECT * FROM chats WHERE is_planner_main = 1;
```

## Сценарий 3: Рабочая память - создание этапов (human-in-the-loop)

**Цель:** Проверить предложение создания этапов с подтверждением

### Предусловия:
- Пользователь в главном чате PLANNER
- Уже есть базовое понимание проекта

### Шаги выполнения:
1. Написать: "Давай спланируем структуру проекта. С чего начнем?"
2. Отправить
3. Дождаться, пока агент предложит создать этап (это может занять 1-2 сообщения)
4. Когда появится кнопка предложения: "Создать чат 'Проектирование БД'", нажать её
5. Подтвердить создание

### Ожидаемый результат:
- Создан новый чат с `parent_id = <id_главного_чата>`
- ChatEntity содержит `working_summary` с контекстом проекта
- Пользователь перенаправлен в новый чат
- В главном чате появляется сообщение: "Создан чат 'Проектирование БД'"

### Проверка в БД:
```sql
-- Проверка структуры чатов
SELECT c1.title as parent, c2.title as stage, c2.working_summary
FROM chats c1
JOIN chats c2 ON c2.parent_id = c1.id
WHERE c1.is_planner_main = 1;

-- Должен быть не-null working_summary во втором чате
```

## Сценарий 10: Комбинированная проверка

**Цель:** End-to-end тест всех трёх слоёв памяти

### Шаги:
1. Создать PLANNER группу "Сайт-портфолио"
2. В главном чате сказать: "Я фотограф, специализируюсь на портретах"
   → **Проверка LTM**: сохранение профессии
3. Создать этап "Выбор платформы"
4. В этапе спросить: "Что лучше для портфолио?"
   → **Проверка Working Memory**: агент знает что "портфолио для фотографа"
5. Сказать: "Остановимся на Tilda, простой конструктор"
   → **Проверка Short-term**: агент помнит выбор в этом чате
6. Завершить этап
   → **Проверка артефактов**: сохранение решения
7. Вернуться в главный чат, создать этап "Наполнение"
8. В этапе "Наполнение" спросить: "Какие фото разместить?"
   → **Проверка Working Memory + LTM**: агент помнит "портреты" из LTM и платформу из главного чата

### Ожидаемый результат:
Все три слоя работают вместе:
- **Short-term**: Немедленный контекст диалога
- **Working**: Саммари от родителя доступно детям
- **Long-term**: Глобальные знания о пользователе везде

## Сценарий 11: Наблюдение за слоями памяти (Debug UI)

## Возможные ошибки и отладка

### Ошибка: Этапы не создаются
**Проверить:**
1. Регулярное выражение в `ToolResponseParser` на `CREATE_STAGE[...]`
2. Корректность system prompt в `PlannerPromptBuilder`
3. Логи: `StageCreationSuggested` событие приходит?

### Ошибка: LTM не сохраняется
**Проверить:**
1. LLM вызывает паттерн `SAVE_FACT[key:category:fact]`?
2. Событие `FactSaved` генерируется?
3. Upsert в `LongTermMemoryRepository` работает?

### Ошибка: Нет наследования контекста
**Проверить:**
1. `working_summary` заполнен в дочернем чате?
2. `PlannerPromptBuilder.buildStagePrompt` вызывается?
3. В системный промпт подставляется `workingSummary`?
