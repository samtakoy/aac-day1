## Q1: "какие основные возможности агента, какой класс реализует"
Основные возможности AI-агента реализованы через фичи (features), которые могут быть добавлены в различные конвейеры (pipelines) внутри одного агента. Каждая фича может предоставлять специфическую функциональность и возможности настройки для агента.

[КЛАСС 1] `AIAgentFeature` [КЛАСС 2] `AIAgentPlanner` реализуют соответствующие механизмы, обеспечивающие эти возможности. А класс `AIAgentPlaner` отвечает за построение и выполнение планов до тех пор, пока они не будут завершены.

У агента есть несколько видов фичей:

1. **Графовые фичи**:
   - Описание: Эти фичи могут быть установлены в конвейеры типа `AIAgentGraphPipeline`. 
   - Методы: Интерфейс графовой фичи (AIAgentGraphFeature) предоставляет метод `install`, который устанавливает данную фичу в указанный конвейер.

2. **Функциональные фичи**:
   - Описание: Эти фичи могут быть установлены в конвейеры типа `AIAgentFunctionalPipeline`.
   - Методы: Интерфейс функциональной фичи (AIAgentFunctionalFeature) также предоставляет метод `install`.

3. **Планировочные фичи**:
   - Описание: Эти фичи могут быть установлены в конвейеры типа планирования (`AIAgentPlannerPipeline`).
   - Методы: Интерфейс планировочной фичи (AIAgentPlannerFeature) также предоставляет метод `install`.

Агент также имеет базовый класс `AIAgentPlanner`, который является точкой входа для выполнения планов. Этот класс отвечает за следующие основные операции:

1. **Построение плана**: Метод `buildPlan` [КЛАСС 2] строит план на основе текущего состояния и предыдущего плана.
   
2. **Выполнение шага плана**: Метод `executeStep` выполняет один шаг построенного плана.

3. **Проверка окончания плана**: Метод `isPlanCompleted` проверяет, завершен ли текущий план или нет.

4. **Основной цикл планирования**: Метод `execute` управляет процессом выполнения различных шагов, построение новых планов и повторное выполнение до тех пор, пока не будет достигнута полная конфигурация.

Таким образом, конкретные возможности агента определяются теми фичами, которые он поддерживает, включая их установку и взаимодействие с различными конвейерами пайплайна. Класс `AIAgentFeature` и конкретный функционал реализован через фичи для различных типов пайплайнов (графовых, функциональных, планировочных).

## Q2: "как конфигурируется агент"
AI-агент конфигурируется с помощью классов и интерфейсов из пакета `ai.koog.agents.core.agent`. Основные шаги и методы для конфигурирования агента включают:

### 1. **Интерфейс AIAgentConfigBase** [КЛАСС 1]
Этот базовый интерфейс определяет ключевые элементы, необходимые для настройки AI-агента:
- `public val prompt: Prompt` — Определяет шаблон или структуру запросов к языковой модели.
- `public val model: LLModel` — Указывает конкретный экземпляр Large Language Model (LLM) для генерации ответов.

### 2. **API AIAgentServiceBuilder** [КЛАСС 2]
Интерфейс `AIAgentServiceBuilderAPI` предоставляет методы, которые используются для установки необходимых компонентов и настроек в процессе конструирования агента:
- `public fun promptExecutor(promptExecutor: PromptExecutor): AIAgentServiceBuilderAPI`
  - Устанавливает экземпляр `PromptExecutor`, отвечающий за выполнение подсказок (prompts) по отношению к языковой модели.
  
- `public fun llmModel(model: LLModel): AIAgentServiceBuilderAPI` 
  - Устанавливает экземпляр LLM, который будет использоваться для операций агента.

- `public fun toolRegistry(toolRegistry: ToolRegistry): AIAgentServiceBuilderAPI`
  - Разрешает настройку метаданных инструментов, доступных в процессе выполнения операций агента.

- `public fun systemPrompt(systemPrompt: String): AIAgentServiceBuilderAPI` 
  - Устанавливает системную подсказку (system-level prompt), определяющую поведение AI-агента внутри системы. 

### 3. **Класс AIAgentBuilder** [КЛАСС 3]
Этот класс предоставляет узкоспециализированные методы для конфигурирования агента:
- `id(id: String)` — Устанавливает уникальное имя или идентификатор для конкретного экземпляра AI-агента.
  
- `withToolRegistry(toolRegistry: ToolRegistry)` 
  - Привязывает конкретный набор инструментов к экземпляру агента.

- `withPromptExecutor(promptExecutor: PromptExecutor?)` 
  - Разрешает настройку конкретного подсказывателя или позволяет установить ее как по умолчанию, при необходимости.
  
Эти методы вместе позволяют разработчикам создавать и настраивать AI-агентов с требуемыми характеристиками и поведением. Функциональность агента включает общение через определенные подсказки (prompts), использование конкретных инструментов, применение правил стратегий или конфигураций работы.

Таким образом, процесс настройки AI-агента состоит из следующих шагов:
1. Определить основные элементы через `AIAgentConfigBase`.
2. Конфигурировать агент с помощью методов из `AIAgentServiceBuilderAPI`, предоставляя конкретные реализации и настройки.
3. Настроить отдельные аспекты поведения через класс `AIAgentBuilder` на уровне более низкого уровня.

## Q3: "как агент работает с историей сообщений"
AI-агенты в контексте данного проекта используются для взаимодействия и выполнения задач, основываясь на истории сообщений. Процесс работы с историей сообщений реализован через класс `AIAgentHistory` [КЛАСС 4], который представляет собой абстрактный базовый класс, обеспечивающий способность хранить и обрабатывать предыдущие сообщения.

### Хранилище Истории Сообщений

Интерфейс `AIAgentMessageRepository` [КЛАСС 6] определяет контракт для хранилища сообщений, которое агент использует для хранения и получения истории сообщений. Этот интерфейс имеет следующие ключевые методы:

- `save(message: ChatMessage)`: Сохраняет указанный объект `ChatMessage` в репозитории.

- `load(fromIndex: Int, count: Int): List<ChatMessage>`:
  - Загружает последовательность сообщений из указанного индекса и переданное количество элементов. Это полезно для запросов к истории приложения или диалога с учетом её истории.

### Обработка Истории

Класс `AIAgentHistory` [КЛАСС 4] предоставляет методы для работы со структурой сообщений:
- Метод `storeMessage(message: ChatMessage)`: Сохраняет переданное сообщение в хранилище истории. Он вызывает `save(message)` из репозитория сообщений [ИСТОЧНИК 10].

- Метод `retrieveHistory(startIndex: Int, count: Int): List<ChatMessage>`:
  - Извлекает историю сообщений с начального индекса в указанных количестве элементов. Он вызывает метод `load(fromIndex, count)` из репозитория сообщений [ИСТОЧНИК 10].

### Применение

Работа с данными истории начинается путем инициализации хранилища сообщений через инсталляцию, предоставленную интерфейсом `AIAgentMessageRepository`. Затем история сообщений используется при обработке запросов или ответов от агента. Например:
- При приеме нового сообщения агент сохраняет его в истории с помощью соответствующих методов (`storeMessage`), чтобы обеспечить непрерывность диалога.
- В ответ на запросы, требующие контекстного понимания предыдущих сообщений, агент использует `retrieveHistory`, чтобы извлечь необходимую историю и использовать её для уточнения своего ответа.

### Использование в Практике

Все это обеспечивает основу для эффективной коммуникации AI-агентов с системой и другими участниками диалога. Наследники класса `AIAgentHistory` могут добавлять дополнительные методы или поведение, чтобы оптимизировать процессы хранения, извлечения или анализа сообщений в зависимости от конкретных требований.

    operator fun get(contextKey: ContextKey<*>): String? {
